# Museum Dilettante

Інтерактивна музейна гра: учасники відповідають числами зі своїх телефонів, ведучий керує раундами, проектор показує результати й випадкові покарання.

## Запуск

1. Створіть Supabase project.
2. Відкрийте SQL Editor та виконайте `supabase/schema.sql`, потім `supabase/admin.sql`, а далі `supabase/punishments.sql`. Це створить ігровий бекенд, колоди та захищений редактор.
3. Скопіюйте `.env.example` у `.env.local` і заповніть `VITE_SUPABASE_URL` та `VITE_SUPABASE_ANON_KEY` (publishable/anon key, **не** service_role).
4. Запустіть `npm install` і `npm run dev`.
5. Імпортуйте репозиторій у Vercel. Framework: Vite, Build: `npm run build`, Output: `dist`. Додайте дві змінні середовища у Vercel.
6. Відкрийте публічний HTTPS-сайт, перейдіть у «Я ведучий» та створіть кімнату. Виведіть `/screen/CODE` на проектор, а QR з пульта покажіть учасникам.

## Маршрути

- `/`: головна
- `/host`: створення кімнати, вибір колоди й керування грою
- `/admin`: адміністрування колод і питань із підтвердженням email
- `/join/CODE`: підключення гравця
- `/screen/CODE`: екран проектора

## Безпека та механіка

Правильні відповіді зберігаються лише в Supabase, у frontend bundle їх немає. Таблиці питань, токенів, гравців та відповідей закриті RLS; доступ здійснюється через `game_api`. Гравці бачать правильну відповідь лише після reveal. Керування раундами потребує секретного UUID ведучого, що зберігається локально в браузері.

Realtime-події з відкритої таблиці `game_public` дають швидкі оновлення, а інтервал 3 секунди — резервну синхронізацію. Після оновлення сторінки ведучого його ключ зберігається у локальному сховищі. Після оновлення сторінки гравець автоматично відновлює сесію у тій самій кімнаті на тому самому пристрої.

**Важливо:** це перша версія, яка потребує налаштування Supabase та Vercel і живої перевірки з кількох пристроїв. Не використовувати для персональних даних чи цінних призів без додаткової авторизації, rate limits і тестів навантаження.

## Адміністрування

Для редагування питань відкрийте `/admin`. Вхід захищений Supabase Auth; доступ має лише підтверджена адреса, включена в `public.quiz_admin_emails`. Публічні учасники не можуть читати правильні відповіді до відкриття раунду.

Одноразове налаштування для magic link: в Supabase Dashboard відкрийте **Authentication → URL Configuration**. У Site URL вкажіть публічну адресу Vercel, а в Redirect URLs додайте `https://museum-dilettante-git-feat-f-722144-bonddesign85-9811s-projects.vercel.app/**`. Дозволені URL обов'язкові для переходу з листа назад у `/admin`.

Редактор уміє створювати колоди, редагувати питання, числові відповіді, пояснення, складність та активність. Для імпорту використовуйте CSV/UTF-8 із заголовками `question,answer,unit,explanation,difficulty,active`; порожня `active` вважається активною. Кнопка «Вимкнути» архівує запитання без його видалення, щоб не псувати вже створені ігрові сесії.

Колоди на екрані ведучого підтягуються з бази автоматично. Нові й редаговані питання беруть участь у **нових** кімнатах, у вже запущених кімнатах список ID фіксований.

## Вхід без ліміту листів Supabase

Основний варіант: **Google OAuth** (кнопка `Увійти через Google` на `/admin`). Він не використовує вбудовану поштову відправку Supabase і працює з поточною серверною перевіркою підтверджених адрес `@ofam.ua` та головного Gmail. Пошта/пароль залишаються альтернативами.

Перед використанням кнопки **обов'язково** налаштуйте постачальника Google у Supabase:
1. У [Google Auth Platform](https://console.cloud.google.com/auth/overview) створіть OAuth клієнт **Web application**. Налаштуйте Audience, Branding та scopes `openid`, `email`, `profile`.
2. Authorized JavaScript origin: `https://museum-dilettante-git-feat-f-722144-bonddesign85-9811s-projects.vercel.app`.
3. Authorized redirect URI: `https://owrsytlgmiykjiistijk.supabase.co/auth/v1/callback`.
4. В [Supabase Auth Providers](https://supabase.com/dashboard/project/owrsytlgmiykjiistijk/auth/providers) увімкніть **Google**, вставте Client ID і Client Secret, збережіть. Ніколи не додавайте Client Secret до GitHub або Vite env.
5. У Supabase Authentication > URL Configuration перевірте, що redirect `https://museum-dilettante-git-feat-f-722144-bonddesign85-9811s-projects.vercel.app/**` дозволено.
6. Увійдіть через кнопку Google й перевірте читання та редагування з підтвердженим `@ofam.ua`. Якщо корпоративні акаунти музею не керуються Google / не мають Google-входу, цей метод не забезпечить автентифікацію власне корпоративної скриньки — знадобиться OAuth її реального постачальника (наприклад, Microsoft Entra ID).

Google OAuth усуває **саме ліміт відправлення email**; загальні обмеження API й захист від зловживань залишаються.

## Права адміністратора

Доступ до `/admin` визначається на сервері у функціях `public.is_quiz_admin()` та `public.is_quiz_owner()` із `supabase/domain-admin-access.sql`.

- Головний адміністратор: `bonddesign85@gmail.com` (підтверджена пошта).
- Редактори музею: будь-яка **підтверджена** адреса з точним доменом `@ofam.ua`.
- Інші пошти не отримують доступ навіть якщо раніше були вручну внесені до `quiz_admin_emails`.
- Перегляд правил доступу доступний тільки головному адміністратору.
- Функція ручного керування списком `manage_quiz_admins` видалена; додавати адреси `@ofam.ua` вручну не потрібно.

Перший вхід — через підтвердження пошти Supabase; після входу можна налаштувати пароль. Поштовий ліміт Supabase Free продовжує діяти для першої авторизації. Запуск нової SQL-інсталяції: `schema.sql`, `admin.sql`, `punishments.sql`, `admin-users.sql`, `domain-admin-access.sql` саме в такому порядку.

## Покарання та режими

В адмінпанелі `/admin` перемкніться на вкладку **Покарання**. Тут можна додавати й змінювати текст завдання, категорію, активність і необов'язкову прив'язку до запитання. Вимкнення зберігає історію раундів.

Налаштування режиму вибору зберігається в `quiz_settings` і **копіюється в нову кімнату** при її створенні. Вже створені кімнати не змінюють режим автоматично.

- `random`: випадковий вибір невикористаного в кімнаті активного покарання, повторення заборонені.
- `no_repeat`: як і в інших режимах, кожний вирок використовується не більше одного разу за сеанс. Після вичерпання списку новий вирок не видається.
- `linked`: спершу невикористане активне покарання, прив'язане до поточного запитання; за відсутності — загальне (без прив'язки); якщо загальних немає — інше невикористане активне. Повтори заборонені.

Якщо всі активні покарання вже використані в цьому сеансі (або активних немає), система не видає завдання й не нараховує штраф. Навіть дублікати однакового тексту з різними ID не можуть випасти двічі за сеанс. Якщо відповідь подала лише одна людина або всі вгадали правильно, покарання теж не призначається. Текст обраного завдання зберігається в історії конкретного раунду.
